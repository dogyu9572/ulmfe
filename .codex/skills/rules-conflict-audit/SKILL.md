# 규칙 충돌 감사

## 목적

이전 프로젝트의 좋은 개발 관점은 유지하되, 현재 프로젝트의 언어/프레임워크/디렉터리/배포 방식과 충돌하는 지시를 제거한다.

## 감사 순서

1. 요청을 설명, 소스 수정, API/DB, UI, 서버 설정, git 작업으로 분류한다.
2. 현재 프로젝트 구조에 맞는 앱, 모듈, 레이어를 구분한다.
3. 금지 대상부터 확인한다: 비밀번호 커밋, 실제 env 수정, 운영 서비스 변경, DB 데이터 변경.
4. 특정 프레임워크 전용 규칙이 섞였는지 확인하고 현재 기술 스택 기준으로 바꾼다.
5. 사용자 요청 범위와 부가 개선을 분리한다.

## 주요 충돌 예시

- Laravel/Blade 규칙을 Spring/React 프로젝트에 그대로 적용하지 않는다.
- Spring/MyBatis 규칙을 Laravel 프로젝트에 그대로 적용하지 않는다.
- 개발서버 dev mode와 운영 배포 방식을 섞지 않는다.
- 로그, 빌드 결과물, 실제 env, DB 덤프는 기본적으로 git에 올리지 않는다.

## 출력

- 적용할 규칙
- 제외할 이전 프로젝트 규칙
- 필요한 사용자 확인 사항
- 최소 수정 제안
